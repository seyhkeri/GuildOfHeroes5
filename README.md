## Практическая работа №5

1. **Кто теперь проверяет повтор при добавлении и почему не Program?**
Теперь повтор проверяет сама гильдия внутри метода AddHero с помощью FindHeroByName. Если оставить проверку в Program, она сработает только там, где о ней не забыли, а любой другой участок кода сможет обойти правило и добавить дубликат. Гильдия сама отвечает за целостность своего состава.

2. **Когда FindHeroByName возвращает null?**
Метод возвращает null в двух случаях: если передана пустая строка или строка из одних пробелов, а также если цикл прошёл по всему списку _heroes и не нашёл ни одного героя с подходящим именем.

3. **Зачем очищать запрос, если имена героев уже очищены?**
Поисковый запрос приходит извне, где могут быть случайные пробелы по краям. Чтобы сравнение корректно нашло уже очищенное имя "Артём", запрос тоже нужно предварительно обработать через Trim().

4. **Почему MemberCount не хранит число, а вычисляет его?**
Вычисляемое свойство каждый раз возвращает актуальное значение _heroes.Count. Это исключает рассинхронизацию: не нужно заводить отдельное поле-счётчик и следить, чтобы оно обновлялось при каждом добавлении или удалении героя.

5. **Удаление из гильдии уничтожает героя?**
Нет, не уничтожает. Метод RemoveHero удаляет только ссылку на объект из внутреннего списка гильдии _heroes. Сам объект Hero продолжает существовать в памяти, пока на него ссылается хотя бы одна переменная в программе.

6. **Почему private-поле не защищено, если вернуть его из метода?**
Модификатор private скрывает только имя поля, запрещая обращаться к _heroes напрямую. Но если метод вернёт ссылку на сам этот список, внешний код получит полный доступ к оригиналу и сможет изменить его через Add() или стереть через Clear(). Поэтому наружу нужно отдавать копию списка.

**Трассировка:** прогноз совпал с фактом (True, False, True, True, 1, 2, True). Всего в коде создано 3 объекта Hero, но в гильдию попали только двое, а после удаления остался 1. В snapshot.Count осталось 2, потому что копия списка была снята до вызова RemoveHero.
**Ошибка 1:** return null стоит внутри цикла foreach. Из за этого метод завершается сразу после проверки первого героя, если его имя не совпало, и до остальных элементов очередь не доходит. Исправление: убрать return null из тела цикла, оставив только один return null после цикла.
**Ошибка 2:** метод GetMembers возвращает ссылку на оригинальный список _heroes вместо копии. Модификатор private не спасает, так как ссылка на объект передана наружу, и в пробе copy.Clear() очистит саму гильдию. Исправление: создавать внутри GetMembers новый List<Hero>, копировать туда ссылки и возвращать его.
**Самостоятельный шаг:** FindStrongest возвращает Hero?, потому что гильдия может быть пустой и самого здорового героя может не существовать - в этом случае вернётся null. CountHealthy возвращает int, так как количество всегда является конкретным числом. Если вызывающий код получил null, он обязан проверить результат через if (strongest != null) перед обращением к его свойствам, иначе программа упадет с NullReferenceException.

### Личный проект
**Ключ:** выбрано свойство Title, так как в каталоге игр пользователь ищет нужный тайтл и проверяет наличие дублей именно по наименованию.
**Когда ключ может подвести:** если потребуется добавить в каталог оригинальную игру и её одноимённый ремейк или перезапуск разных лет выпуска.
**Обработка null:** если игры с искомым названием нет в каталоге, метод FindGameByTitle возвращает null. В Program результат сохраняется в переменную типа Game? и проверяется конструкцией if (foundGame != null) до чтения свойств объекта, а в ветке else выводится сообщение, что игра не найдена.
